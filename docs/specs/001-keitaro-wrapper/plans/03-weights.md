# Распределение весов — план реализации

> Исполнитель: `superpowers:executing-plans`. Спецификация: [../spec.md](../spec.md).

**Цель:** AC4.1–AC4.6, стабильное распределение ровно 100%.
**Архитектура:** чистая функция; не читает БД/API и не меняет вход.
**Стек:** Python, pytest, Hypothesis.

## Задачи

- [x] W1. `tests/test_weights.py`: [], [None], три/четыре None, [25,None,None],
  несколько закреплений, все закреплены, сумма >100, нулевой остаток,
  более 100 офферов, недопустимые bool/float/отрицательные/101.
  Инварианты: сумма 100, pins сохранены, незакреплённые отличаются ≤1.
  Запуск `uv run --extra dev pytest tests/test_weights.py -q`: RED → GREEN.
- [x] W2. `app/weights.py`: `distribute(pins: list[int | None]) -> list[int]`.
  Пустой список даёт []; divmod остатка, лишний 1% первым в списке.
  Допустимы pins 0..100 и нулевые незакреплённые доли; лимит в 100 офферов
  из-за целочисленных процентов не вводится. При недопустимом бюджете —
  DomainError 422 с code weight_budget, без частичного результата.

**Выход:** редактор передаёт только активные строки в стабильном порядке;
архивные веса редактор устанавливает в 0 отдельно.
**Приёмка:** VT3; пример 25/38/37; property-based проверки.

Уточнение исполнителя перед реализацией: прежний минимум 1% был добавлен
без требования ТЗ и удалён. Нулевой вес не равен архивному состоянию;
статус привязки обрабатывает редактор на этапе 4 отдельно от расчёта долей.

Результат: 27 тестов алгоритма и 64 теста полного набора проходят.
Независимое read-only review не нашло значимых замечаний. Basedpyright файла
app/weights.py, ruff check и format check проходят.
