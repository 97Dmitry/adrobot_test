# Обёртка над Keitaro

Тестовое Adrobot: создание кампаний с двумя потоками и редактор офферов.
Стек: FastAPI, SQLAlchemy 2, Alembic, SQLite; интерфейс — HTML/JavaScript.

Разработка идёт по этапам с отдельным PR и приёмкой каждого этапа.
Требования и сценарии: [spec.md](docs/specs/001-keitaro-wrapper/spec.md).
Порядок работ: [plan.md](docs/specs/001-keitaro-wrapper/plan.md).

## Текущее состояние

Доступны создание кампаний, редактор офферов, JSON API и веб-интерфейс.
Последний этап подготовлен отдельным PR для приёмки.

Создаватор проверяет справочники, создаёт выключенную кампанию, добавляет
гео-поток на Google и поток с оффером. Он включает кампанию только после
повторного чтения и проверки настроек обоих потоков.

Расчёт весов сохраняет закреплённые целые проценты и поровну распределяет
остаток. Например: три оффера → 34/33/33; один закреплён на 25%, два свободны
→ 25/38/37. Закрепление 100% оставляет другим по 0%. При равном делении лишние
проценты получают первые незакреплённые строки в стабильном порядке.

Редактор хранит опубликованный снимок и черновик отдельно. Add/Remove/Bring back
и Pin меняют локальное состояние; Publish отправляет только offers, Cancel
восстанавливает опубликованное. Удалённые привязки остаются в архиве. Sync
импортирует внешние изменения и не затирает черновики. Конфликты одновременных
запросов обнаруживаются по ревизии SQLAlchemy в транзакции БД.

## Установка и миграции

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Проверенная версия uv — 0.12.22. Команды выполняются из корня проекта.

```sh
uv sync --frozen --extra dev
```

Создайте локальный `.env` из `.env.example`:

```sh
# Linux / WSL / macOS
cp .env.example .env
```

```bat
rem Windows cmd
copy .env.example .env
```

Заполните `KEITARO_URL` и `KEITARO_API_KEY`. URL — адрес вашего тестового
сервера, без `/admin_api/v1`; пример в `.env.example` указывает на сервер задания.
Ключ не нужен для локальных автоматических тестов. `.env` и файлы SQLite
исключены из Git; ключ используется только сервером.

```sh
uv run alembic upgrade head
uv run alembic current
```

Схема не создаётся автоматически при запуске. Новые миграции добавляются
отдельными версиями Alembic. `downgrade base` удаляет все таблицы приложения
и данные: используйте его только на одноразовой тестовой БД, как в тестах.

## Запуск

```sh
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).
Остановка — Ctrl+C. Синхронные HTTP-обработчики FastAPI работают в thread pool;
каждый запрос получает отдельную SQLAlchemy Session. Общего lock или требования
единственного worker нет.

По умолчанию разрешены локальные Host; запросы изменения с чужого origin и
без `Content-Type: application/json` отклоняются. Учётных записей и авторизации
в приложении нет: запуск выше слушает loopback. Для доступа через сеть потребуется
внешняя авторизация и настройка `ALLOWED_HOSTS` как JSON-массива имён хостов.
Это ограничение доступа, а не ограничение числа операторов.

## Сценарий демонстрации

1. В форме создания укажите суффикс имени, страны (например, `AU, MX`), оффер,
   домен, группу и источник из Keitaro. Префикс `test_tsybizov_` добавляется сервером.
2. Нажмите «Создать кампанию». На экране появятся ID, ссылка и два потока.
   Ссылку можно скопировать; приложение не открывает её и не создаёт клики.
3. В потоке офферов найдите новый оффер по ID или названию, выберите его из
   списка и нажмите «Добавить». Поток станет жёлтым; веса пересчитаются.
4. Cancel отменяет черновик. Publish отправляет офферы в Keitaro и сохраняет
   опубликованное состояние. Remove оставляет серую строку, Bring back возвращает её.
5. Введите целый вес 0..100 и нажмите Pin. Unpin возвращает долю к равному
   распределению. Архивное закрепление сохраняется до Bring back.
6. Перезагрузите страницу: черновик восстановится из БД. «Обновить экран» читает
   локальное состояние, «Синхронизировать с Keitaro» загружает внешние изменения.
   Sync при черновике запрещён; его нельзя использовать для молчаливого сброса.

В «Открыть кампанию» доступен поиск и ввод ID. Поля поиска используют клавиатурный
выбор из списка; Enter в поле добавления отправляет выбранный числовой ID.
Для демонстрационных записей используйте собственную тестовую кампанию.

Создание сохраняет ключ операции в браузере. Повтор с теми же параметрами,
включая повтор после перезагрузки/потери ответа, использует тот же ключ.
Изменение параметров само по себе не меняет ключ: для следующей кампании
нажмите «Начать новую операцию». При неизвестном
исходе сначала сверяйте предыдущую операцию; новая операция не отменяет старую.

## HTTP API

Контракт доступен в `/openapi.json`; UI не зависит от CDN. Основные маршруты:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | HTTP-сервер запущен; подключение Keitaro проверяется каталогами |
| GET | `/api/catalogs`, `/api/offers?q=`, `/api/campaigns?q=` | Справочники и поиск |
| POST | `/api/campaigns` | Создание с заголовком `Idempotency-Key` |
| GET | `/api/operations/{key}` | Состояние операции создания |
| GET | `/api/campaigns/{id}` | Сохранённое локальное состояние |
| POST | `/api/campaigns/{id}/sync` | Импорт из Keitaro |
| POST | `/api/streams/{id}/offers` | Add: `offer_id`, `revision` |
| PATCH | `/api/streams/{id}/offers/{offer_id}` | `action`, `revision`, для pin — `pin` |
| POST | `/api/streams/{id}/publish`, `/cancel` | Публикация/отмена с `revision` |

`action`: `remove`, `restore`, `pin`, `unpin`. Сервер возвращает ошибку в
`{"error":{"code":"...","message":"..."}}`; конфликт ревизии — HTTP 409.
Чтение из другой вкладки не обновляет эту вкладку автоматически: используйте
«Обновить экран». Секрет Keitaro браузеру не передаётся.

## Проверки

```sh
uv run --frozen --extra dev pytest -q
uv run --frozen --extra dev ruff check app tests migrations
uv run --frozen --extra dev ruff format --check app tests migrations
```

Тесты используют временную SQLite и `httpx.MockTransport`; реальный Keitaro
ими не изменяется. Проверяются payload и порядок действий, валидация,
частичные сбои, потерянные ответы, повторные запросы и миграции.
Результаты по критериям: [verification.md](docs/specs/001-keitaro-wrapper/verification.md).

Браузерные тесты используют локальный fake Keitaro и временную БД, проверяют
desktop и mobile. Установка Chromium и запуск в WSL/Linux:

```sh
uv run --frozen --extra dev playwright install chromium
RUN_BROWSER=1 uv run --frozen --extra dev pytest tests/browser -q
```

Если Playwright сообщает об отсутствующих системных библиотеках Linux,
установите зависимости Chromium для вашей ОС. Для Windows cmd:

```bat
uv run --frozen --extra dev playwright install chromium
cmd /C "set RUN_BROWSER=1&& uv run --frozen --extra dev pytest tests/browser -q"
```

В CI Chromium устанавливается с системными зависимостями, браузерные тесты
обязательны. Скриншоты локальной проверки сохраняются в исключённый `.artifacts/`.

Опциональный интеграционный тест работает с реальным тестовым Keitaro, создаёт
кампанию `test_tsybizov_*` и выключает её после проверки. Для WSL/Linux:

```sh
RUN_KEITARO_LIVE=1 uv run --frozen --extra dev pytest tests/test_editor_live.py -q -s
```

Для Windows cmd переменная ограничена дочерним процессом:

```bat
cmd /C "set RUN_KEITARO_LIVE=1&& uv run --frozen --extra dev pytest tests/test_editor_live.py -q -s"
```

Полный интеграционный сценарий через HTTP API (также создаёт и выключает
собственную кампанию):

```sh
RUN_HTTP_LIVE=1 uv run --frozen --extra dev pytest tests/test_http_live.py -q -s
```

```bat
cmd /C "set RUN_HTTP_LIVE=1&& uv run --frozen --extra dev pytest tests/test_http_live.py -q -s"
```

При неизвестном результате PUT редактор сохраняет intent и блокирует изменения.
Следующий Publish сверяет состояние без повторной записи. Чтение прежних весов
не означает, что сервер закончил PUT; пока применение не подтверждено, требуется
ручная сверка в Keitaro. Если ответ PUT подтвердил target, но затем прочитаны
другие веса, это внешний конфликт и доступна отмена локального черновика.
Admin API не поддерживает условный PUT: внешняя правка между проверкой снимка
и записью остаётся гонкой. Локальная ревизия защищает запросы обёртки,
но не делает запись в Keitaro атомарной относительно его собственного интерфейса.

При реальных проверках создаются только кампании `test_tsybizov_*`.
Трекинговые ссылки не открываются: настройка маршрутизации проверяется через
Admin API, а фактический редирект по IP требует отдельной проверки с нужным IP.
