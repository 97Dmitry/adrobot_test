# Adrobot — обёртка над Keitaro

Тестовое задание: создание рекламных кампаний и редактор офферов через Keitaro Admin API.
Стек: **FastAPI + SQLAlchemy 2**, Alembic, SQLite, httpx; интерфейс — HTML/CSS/JavaScript.

## Возможности

- Создание кампании с названием, странами, оффером, доменом, группой и источником.
  Первый поток отправляет посетителей из выбранных стран на Google, второй — на оффер.
  Кампания включается только после настройки и проверки обоих потоков.
- Загрузка существующей кампании по ID или через поиск. Потоки без офферов
  отображаются без разбора и изменения их фильтров и перенаправлений.
- Добавление, удаление и восстановление офферов через локальный черновик.
  Удалённые привязки сохраняются в архиве.
- Равномерное распределение целых процентов с закреплением отдельных весов.
  Например: три оффера → 34/33/33; один закреплён на 25% → 25/38/37.
- Сохранение черновиков после перезагрузки, синхронизация внешних изменений
  и обнаружение конфликтов при публикации.

## Быстрый запуск

Нужны Python **3.12** и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Проверенная версия uv — 0.12.22. Все команды выполняются из корня репозитория.

**1. Установите зависимости и создайте `.env`.**

```sh
uv sync --frozen --extra dev
```

Linux / WSL / macOS:

```sh
cp .env.example .env
```

Windows cmd:

```bat
copy .env.example .env
```

**2. Заполните `KEITARO_API_KEY` в `.env`** и проверьте остальные настройки:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `KEITARO_URL` | Адрес сервера Keitaro | `https://tlgk.host` — тестовый сервер задания |
| `KEITARO_API_KEY` | Ключ Admin API | Пустое; для работы UI нужен свой ключ |
| `DATABASE_URL` | Локальная БД приложения | `sqlite:///./adrobot.db` |
| `KEITARO_TIMEOUT` | Таймаут одного запроса, секунды | `20` |
| `ALLOWED_HOSTS` | Разрешённые имена хостов, JSON-массив | `["127.0.0.1","localhost","[::1]"]` |

`KEITARO_URL` указывается без `/admin_api/v1`. Ключ используется сервером и не
передаётся браузеру. `.env`, SQLite и локальные артефакты исключены из Git.
Для автоматических тестов с fake Keitaro настоящий ключ не нужен.

**3. Примените миграции и запустите приложение.**

```sh
uv run --frozen alembic upgrade head
uv run --frozen alembic current
uv run --frozen uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **[http://localhost:8000](http://localhost:8000)**.
Альтернативный адрес — [http://127.0.0.1:8000](http://127.0.0.1:8000).
Остановка сервера — Ctrl+C.

Схема БД не создаётся автоматически при запуске. Изменения схемы оформляются
миграциями Alembic. `alembic downgrade base` удаляет таблицы и данные приложения;
в тестах эта команда используется только на временной БД.

## Работа с интерфейсом

**Открыть кампанию.** Введите ID или часть названия в верхнем блоке поиска,
выберите результат и нажмите «Загрузить потоки». Слева остаётся компактная
панель, справа — редактор. На мобильном экране панель располагается над потоками.

**Создать кампанию.** Раскройте «Новая кампания». Укажите название, страны
(например, `AU, MX`), оффер и настройки из справочников Keitaro. Сервер добавляет
префикс `test_tsybizov_`. После успешного создания форма сворачивается, появляются
ID, ссылка и два потока кампании. Ссылку можно скопировать; приложение её не открывает.

**Поиск.** Результаты показывают ID и название. Выбор доступен мышью или
стрелками ↑/↓ и Enter; Escape закрывает список. Первый Enter выбирает выделенный
результат без отправки операции. Следующий Enter в поле добавления отправляет ID
оффера. При точном совпадении ID название видно в подсказке без раскрытия списка.

**Редактирование потока:**

| Действие | Результат |
|---|---|
| «Добавить» | Добавляет оффер в черновик и пересчитывает веса |
| «Удалить» | Делает строку архивной с весом 0%; удаление из Keitaro произойдёт при публикации |
| «Вернуть» | Возвращает архивный оффер в черновик |
| «Закрепить» / «Сохранить» | Фиксирует целый вес 0..100; остальные офферы делят остаток |
| «Снять» | Снимает закрепление и пересчитывает веса |
| «Опубликовать» | Передаёт в Keitaro только массив офферов выбранного потока |
| «Отменить» | Восстанавливает опубликованное состояние и убирает новые неопубликованные привязки |

Жёлтый поток — черновик; серая строка — архив. Статусы дополнительно обозначены
текстом. Нулевой вес активного оффера не переводит его в архив. Пустой набор
можно сохранить как черновик, но опубликовать нельзя.

«Обновить экран» читает локальное состояние. «Синхронизировать с Keitaro»
загружает внешние изменения и сохраняет историю удалённых офферов. Синхронизация
при черновиках запрещена; при открытии такой кампании показывается её локальная
версия. Если закреплённый вес изменили в Keitaro, при синхронизации закрепление снимается.

Ключ создания и исходные параметры сохраняются в браузере. Повтор после
перезагрузки или потери ответа использует тот же ключ. Изменение регистра страны
или добавление префикса не создаёт новую операцию. Для другой кампании нажмите
«Начать новую операцию». При неизвестном исходе сначала сверяйте предыдущую:
новая операция не отменяет предыдущую запись в Keitaro.

## Проверки

Обычные тесты используют временную SQLite и fake Keitaro, не изменяя тестовый аккаунт:

```sh
uv run --frozen --extra dev pytest -q
uv run --frozen --extra dev ruff check app tests migrations
uv run --frozen --extra dev ruff format --check app tests migrations
```

Браузерные тесты требуют Chromium. Linux / WSL / macOS:

```sh
uv run --frozen --extra dev playwright install chromium
RUN_BROWSER=1 uv run --frozen --extra dev pytest -q
```

Windows cmd:

```bat
uv run --frozen --extra dev playwright install chromium
cmd /C "set RUN_BROWSER=1&& uv run --frozen --extra dev pytest -q"
```

Если Playwright сообщает об отсутствующих системных библиотеках Linux, установите
зависимости Chromium для своей ОС. В CI браузер устанавливается с зависимостями;
браузерные тесты обязательны. Для запуска только UI-сценариев замените `pytest -q`
на `pytest tests/browser -q`.

Зафиксированный результат UI/UX-итерации: **132 passed, 2 skipped**, включая
**13 браузерных сценариев** для desktop/mobile. Два live-теста по умолчанию
пропускаются. Проверяются миграции, веса, черновики, архив, конфликты, потерянные
ответы, повторные запросы, клавиатура и сохранение состояния после перезагрузки.
Скриншоты сохраняются локально в `.artifacts/`.

### Проверки реального Keitaro

Эти тесты включаются отдельно, используют ключ из `.env`, создают собственную
кампанию `test_tsybizov_*` и выключают её в конце. Не запускайте их на рабочем аккаунте.
Трекинговые ссылки тестами не открываются.

Linux / WSL / macOS:

```sh
RUN_KEITARO_LIVE=1 uv run --frozen --extra dev pytest tests/test_editor_live.py -q -s
RUN_HTTP_LIVE=1 uv run --frozen --extra dev pytest tests/test_http_live.py -q -s
```

Windows cmd:

```bat
cmd /C "set RUN_KEITARO_LIVE=1&& uv run --frozen --extra dev pytest tests/test_editor_live.py -q -s"
cmd /C "set RUN_HTTP_LIVE=1&& uv run --frozen --extra dev pytest tests/test_http_live.py -q -s"
```

Первый тест проверяет сервис редактора, второй — сценарий через HTTP-маршруты.
Live-тесты отключены в CI. Результаты: [основные проверки](docs/specs/001-keitaro-wrapper/verification.md)
и [проверки UI/UX](docs/specs/002-ui-ux-polish/plan.md).

## HTTP API и устройство проекта

Контракт доступен в `/openapi.json`. Swagger UI и ReDoc отключены; интерфейс
не требует внешних CDN. Для всех запросов изменения, включая Sync без тела,
нужен `Content-Type: application/json`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка HTTP-сервера; доступ к Keitaro проверяется каталогами |
| GET | `/api/catalogs`, `/api/offers?q=`, `/api/campaigns?q=` | Справочники и поиск |
| POST | `/api/campaigns` | Создание с заголовком `Idempotency-Key` |
| GET | `/api/operations/{key}` | Состояние создания |
| GET | `/api/campaigns/{id}` | Локальное состояние |
| POST | `/api/campaigns/{id}/sync` | Импорт из Keitaro |
| POST | `/api/streams/{id}/offers` | Добавление: `offer_id`, `revision` |
| PATCH | `/api/streams/{id}/offers/{offer_id}` | `action`, `revision`; для закрепления — `pin` |
| POST | `/api/streams/{id}/publish`, `/api/streams/{id}/cancel` | Публикация или отмена с `revision` |

Действия PATCH: `remove`, `restore`, `pin`, `unpin`. Ошибки возвращаются в формате
`{"error":{"code":"...","message":"..."}}`; конфликт ревизии — HTTP 409.

- `app/main.py` — HTTP-маршруты и отдельная SQLAlchemy Session на запрос.
- `app/creator.py` — создание кампании и идемпотентность.
- `app/editor.py`, `editor_state.py`, `publication.py` — импорт, черновики и публикация.
- `app/weights.py` — распределение весов; `app/keitaro.py` — клиент Admin API.
- `app/static/` — интерфейс; `migrations/` — миграции; `tests/` — проверки.

Разработка велась через спецификации, проверяемые задачи и отдельные PR:
[основная спецификация](docs/specs/001-keitaro-wrapper/spec.md),
[план реализации](docs/specs/001-keitaro-wrapper/plan.md),
[доработка UI/UX](docs/specs/002-ui-ux-polish/spec.md).

## Ограничения

- Авторизации в приложении нет. Команда запуска слушает loopback; для доступа
  через сеть нужна внешняя авторизация и настройка `ALLOWED_HOSTS`. Запросы
  изменения с чужого origin отклоняются.
- После неизвестного результата PUT изменения блокируются. Следующее нажатие
  «Опубликовать» только сверяет результат без повторной записи. Чтение прежних
  весов не подтверждает завершение PUT; если исход не установлен, требуется ручная
  сверка в Keitaro. Если ответ PUT подтвердил запись, а затем прочитаны другие веса,
  доступна отмена черновика и синхронизация внешнего изменения.
- Admin API не поддерживает условный PUT. Между проверкой снимка и записью
  возможна внешняя правка; локальная ревизия не устраняет эту гонку.
- Браузерные проверки выполнены в Chromium на Linux/WSL. Firefox/Safari,
  системная мобильная клавиатура и реальный запуск Windows не проверялись.
  Геофильтр проверен через Admin API; фактический редирект с разных IP не проверялся.
