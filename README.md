# Обёртка над Keitaro

Тестовое Adrobot: создание кампаний с двумя потоками и редактор офферов.
Стек: FastAPI, SQLAlchemy 2, Alembic, SQLite; интерфейс — HTML/JavaScript.

Разработка идёт по этапам с отдельным PR и приёмкой каждого этапа.
Требования и сценарии: [spec.md](docs/specs/001-keitaro-wrapper/spec.md).
Порядок работ: [plan.md](docs/specs/001-keitaro-wrapper/plan.md).

## Текущее состояние

В этой версии доступны клиент Admin API, миграции, создание кампаний, расчёт весов
и сервис редактора. HTTP-маршруты и веб-интерфейс входят в следующий PR.

Создаватор проверяет справочники, создаёт выключенную кампанию, добавляет
гео-поток на Google и поток с оффером. Он включает кампанию только после
повторного чтения и проверки настроек обоих потоков.

Расчёт весов сохраняет закреплённые целые проценты и поровну распределяет
остаток. Например: три оффера → 34/33/33; один закреплён на 25%, два свободны
→ 25/38/37. Закрепление 100% оставляет другим по 0%. При равном делении лишние
проценты получают первые незакреплённые строки в стабильном порядке.

Редактор хранит опубликованный снимок и черновик отдельно. Add/Remove/Bring back
и Pin меняют локальное состояние; Publish отправляет только offers, Cancel
восстанавливает опубликованное. Удалённые привязки остаются в архиве. Sync
импортирует внешние изменения и не затирает черновики. Конфликты одновременных
запросов обнаруживаются по ревизии SQLAlchemy в транзакции БД.

## Установка и миграции

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Проверенная версия uv — 0.12.22. Команды выполняются из корня проекта.

```sh
uv sync --frozen --extra dev
```

Создайте локальный `.env` из `.env.example`:

```sh
# Linux / WSL / macOS
cp .env.example .env
```

```bat
rem Windows cmd
copy .env.example .env
```

Заполните `KEITARO_URL` и `KEITARO_API_KEY`. URL — адрес вашего тестового
сервера, без `/admin_api/v1`; пример в `.env.example` указывает на сервер задания.
Ключ не нужен для локальных автоматических тестов. `.env` и файлы SQLite
исключены из Git; ключ используется только сервером.

```sh
uv run alembic upgrade head
uv run alembic current
```

Схема не создаётся автоматически при запуске. Новые миграции добавляются
отдельными версиями Alembic. `downgrade base` удаляет все таблицы приложения
и данные: используйте его только на одноразовой тестовой БД, как в тестах.

## Проверки

```sh
uv run --extra dev pytest -q
uv run --extra dev ruff check app tests migrations
uv run --extra dev ruff format --check app tests migrations
```

Тесты используют временную SQLite и `httpx.MockTransport`; реальный Keitaro
ими не изменяется. Проверяются payload и порядок действий, валидация,
частичные сбои, потерянные ответы, повторные запросы и миграции.
Результаты по критериям: [verification.md](docs/specs/001-keitaro-wrapper/verification.md).

Опциональный интеграционный тест работает с реальным тестовым Keitaro, создаёт
кампанию `test_tsybizov_*` и выключает её после проверки. Для WSL/Linux:

```sh
RUN_KEITARO_LIVE=1 uv run --frozen --extra dev pytest tests/test_editor_live.py -q -s
```

Для Windows cmd переменная ограничена дочерним процессом:

```bat
cmd /C "set RUN_KEITARO_LIVE=1&& uv run --frozen --extra dev pytest tests/test_editor_live.py -q -s"
```

При неизвестном результате PUT редактор сохраняет intent и блокирует изменения.
Следующий Publish сверяет состояние без повторной записи. Чтение прежних весов
не означает, что сервер закончил PUT; пока применение не подтверждено, требуется
ручная сверка в Keitaro. Если ответ PUT подтвердил target, но затем прочитаны
другие веса, это внешний конфликт и доступна отмена локального черновика.
Admin API не поддерживает условный PUT: внешняя правка между проверкой снимка
и записью остаётся гонкой. Локальная ревизия защищает запросы обёртки,
но не делает запись в Keitaro атомарной относительно его собственного интерфейса.

При реальных проверках создаются только кампании `test_tsybizov_*`.
Трекинговые ссылки не открываются: настройка маршрутизации проверяется через
Admin API, а фактический редирект по IP требует отдельной проверки с нужным IP.
