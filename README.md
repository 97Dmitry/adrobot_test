# Обёртка над Keitaro

Тестовое Adrobot: создание кампаний с двумя потоками и редактор офферов.
Стек: FastAPI, SQLAlchemy 2, Alembic, SQLite; интерфейс — HTML/JavaScript.

Разработка идёт по этапам с отдельным PR и приёмкой каждого этапа.
Требования и сценарии: [spec.md](docs/specs/001-keitaro-wrapper/spec.md).
Порядок работ: [plan.md](docs/specs/001-keitaro-wrapper/plan.md).

## Текущее состояние

В этой версии доступны клиент Admin API, миграции и сервис создания кампаний
с CLI для проверки. HTTP-маршруты, интерфейс и редактор входят в следующие PR.

Создаватор проверяет справочники, создаёт выключенную кампанию, добавляет
гео-поток на Google и поток с оффером. Он включает кампанию только после
повторного чтения и проверки настроек обоих потоков.

## Установка и миграции

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Проверенная версия uv — 0.12.22. Команды выполняются из корня проекта.

```sh
uv sync --frozen --extra dev
```

Создайте локальный `.env` из `.env.example`:

```sh
# Linux / WSL / macOS
cp .env.example .env
```

```bat
rem Windows cmd
copy .env.example .env
```

Заполните `KEITARO_URL` и `KEITARO_API_KEY`. URL — адрес вашего тестового
сервера, без `/admin_api/v1`; пример в `.env.example` указывает на сервер задания.
Ключ не нужен для локальных автоматических тестов. `.env` и файлы SQLite
исключены из Git; ключ не передаётся в аргументах CLI или браузер.

```sh
uv run alembic upgrade head
uv run alembic current
```

Схема не создаётся автоматически при запуске. Новые миграции добавляются
отдельными версиями Alembic. `downgrade base` удаляет все таблицы приложения
и данные: используйте его только на одноразовой тестовой БД, как в тестах.

## Проверка создавателя через CLI

Сначала получите доступные ID из Keitaro:

```sh
uv run python -m app.cli catalogs
uv run python -m app.cli offers --query "Flexacil"
```

Пример для тестового сервера задания; ID следует сверить с актуальными
справочниками. Команда одной строкой подходит также для Windows cmd:

```sh
uv run python -m app.cli create --name test_tsibizov_example --countries AU,MX --offer-id 25327 --domain-id 1813 --group-id 10332 --source-id 836 --key example-operation-001
```

`--name` может содержать только суффикс: префикс `test_tsibizov_` добавится
автоматически. Страны — реальные ISO alpha-2 коды. Ответ содержит ID кампании,
трекерную ссылку и фазу `complete`.

`--key` — идентификатор операции, а не API-ключ. При повторе той же операции
сохраняйте тот же key и параметры: приложение вернёт сохранённый результат
или выполнит сверку без нового POST. Другие параметры с тем же key отклоняются.
Для отдельной новой кампании используйте новый key.

```sh
uv run python -m app.cli status --key example-operation-001
```

При частичном сбое в ответе сохраняются известный ID и этап остановки.
Проверьте кампанию в Keitaro: приложение намеренно не удаляет частичный
результат и не пытается автоматически достроить его повторными POST.
Потеря ответа на включение означает необходимость сверки, а не гарантированное
отключение кампании. Коды выхода CLI: 0 — успех, 1 — ошибка интеграции/операции,
2 — неверные входные данные.

Не запускайте одновременно CLI-запись и сервер с той же локальной БД.
Приложение рассчитано на один процесс и одного оператора. Согласованность
локальной SQL-транзакции и удалённого Admin API не является общей транзакцией.

## Проверки

```sh
uv run --extra dev pytest tests/test_keitaro.py tests/test_migrations.py tests/test_creator.py tests/test_cli.py -q
uv run --extra dev ruff check app tests migrations
uv run --extra dev ruff format --check app tests migrations
```

Тесты используют временную SQLite и `httpx.MockTransport`; реальный Keitaro
ими не изменяется. Проверяются payload и порядок действий, валидация,
частичные сбои, потерянные ответы, повторные запросы, миграции и CLI.
Результаты по критериям: [verification.md](docs/specs/001-keitaro-wrapper/verification.md).

При реальных проверках создаются только кампании `test_tsibizov_*`.
Трекинговые ссылки не открываются: настройка маршрутизации проверяется через
Admin API, а фактический редирект по IP требует отдельной проверки с нужным IP.
